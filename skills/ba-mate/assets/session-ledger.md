## Trace review

Use the same direction as the JSON contract: upstream evidence/input → downstream artifact. For example, a source supports a requirement, and a requirement supports its criterion. A requirement's citation list points back to evidence; that is not the direction of a `supports` trace. Use only `supports` or `depends-on` for the relationship.

## Approval and baseline

Exact manifest, exclusions and accepted nonblocking issues; actual authorised human decision/time/basis; retained approved content or local snapshot location. If no such decision exists, status is draft or ready for human review. This ledger does not authenticate identity or enforce snapshot immutability.

## Change, recovery and resumption

Prior baseline; trigger; impacted/unaffected items and human rationale; changed revisions; stale dependencies; pending revalidation; new approval if actually given. Record manual recovery without restoring old approval automatically. On resumption disclose missing records and reconcile discrepancies before claiming current approval.
