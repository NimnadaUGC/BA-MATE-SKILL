# Approved change: fictional craft studio

Public synthetic case. Start with the reviewed 36-hour fixture and an explicitly labelled fictional owner decision. Capture its exact R-1/AC-1/D-1 revisions as a baseline. The fictional coordinator then changes the rule to 60 elapsed hours after confirmation.

1. Retain the first baseline, original source answer and approval record.
2. Append E-1 r2. Inspect potential dependency impact: requirement, boundary criteria and document are affected; human checks any other relevant business consequences.
3. Attempt to validate the old approval for current work: it must fail on stale inputs/pending review.
4. Append R-1/AC-1/D-1 r2 with corrected text/references. Reverify traces to current endpoints and explicitly record fictional human revalidation.
5. Record a new fictional owner decision for the exact r2 manifest and capture the second baseline.
6. Export both: the first remains 36 hours, the second 60 hours. Working exports say draft. Optional handover preserves selected BA content without adding technical architecture.

`scripts/rehearse.py` executes this structural sequence and compares the old export byte-for-byte before/after change. Its supplied human fields are simulated fixture data. Installed-host semantic behaviour and real practitioner approval still require separate qualification.
