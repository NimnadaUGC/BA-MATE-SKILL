# Contributing

Use synthetic or sanitised reproductions. Do not submit client/company documents, participant records, private workspaces, credentials, unseen study cases, answer sheets or reviewer keys. Public issues are feedback, not consented study collection.

Change the canonical skill under `skills/ba-mate`; distribution packages are generated. Keep shared governance in one place, mode details in references and templates in assets. Host manifests may change packaging/invocation but must not weaken the human decision boundary or duplicate the framework.

For a change, describe the observed problem, mechanism M1–M7, affected behaviour, verification and remaining limitations. Preserve failed attempts and adverse observations. Do not invent findings to justify a refinement. Keep protocol changes separate from product repairs.

Run helper tests and `scripts/check_project.py`, rebuild packages, and verify installed relative resource paths. Add meaningful behavioural/integrity tests when changing transactions or approval/export rules. Record host/model versions and actual outputs for live-host qualification. Do not label structural tests as semantic review or participant evaluation.

Breaking changes to records increment `schema_version` and require an explicit migration; v1 refuses unknown schemas. Package versions, framework versions and schema versions remain independent. Release archives must contain no private data. Contributions are under Apache-2.0; retain relevant attribution notices.
